## ขั้นตอน

1. ระบุวันที่วันนี้ และงานของสมาชิกคนนี้ในตารางวันของ `SCHEDULE-20-26.md` (ทั้ง feature และเอกสาร)
   - ถ้างานวันก่อนหน้ายังไม่เสร็จ (ดูจาก HANDOFF + ไฟล์จริง) ให้ทำงานที่ค้างก่อน และบอกผู้ใช้ว่าตามหลังตาราง
2. สรุปให้ผู้ใช้ 5 บรรทัด: วันนี้ต้องเสร็จอะไร · งานถัดไป 1 ชิ้น · ไฟล์ที่จะสร้าง/แก้ · FR/NFR ที่เกี่ยวข้อง · สิ่งที่ต้องให้คนตัดสิน
3. ตรวจ branch: ต้องไม่ใช่ `main` · ถ้าอยู่ `main` ให้เสนอคำสั่ง `git checkout -b <ประเภท>/<ชื่อ>` แล้วรอผู้ใช้
4. ทำงานถัดไป **ชิ้นเดียว** ตามประเภท:
   - เอกสาร (Charter / SRS / Design / test / report): ใช้ prompt ของขั้นนั้นใน `ROADMAP.md` เป็นข้อกำหนด
   - feature: ใช้ Spec Kit Full path ตาม `TEAM-PLAN.md` ข้อ 1 ทีละคำสั่ง (`/speckit-specify` ต้องระบุ feature directory
     `specs/00N-ชื่อ` ตามตารางข้อ 3 และอ้าง FR/AC ใน `docs/02-requirements/spec.md` เสมอ)
   - แก้เฉพาะไฟล์ที่สมาชิกคนนี้เป็นเจ้าของ ถ้าต้องแก้ไฟล์คนอื่น ให้หยุดและบอกผู้ใช้ว่าต้องคุยกับใคร
5. ตรวจก่อนจบ:
   - ทุกสิ่งที่สร้างอ้าง FR/NFR ได้ (ไม่มี = ไม่ทำ แจ้งผู้ใช้)
   - โค้ด: `node --test` ผ่าน (รายงานผลจริงที่รัน) · ไม่มี `import`/`export` · ใช้ token · มีป้าย `Covers: FR-x` · มีทางผิด/ว่าง
   - เอกสาร: ไม่มีช่องว่างที่ไม่ได้ตั้งใจ · ข้อมูลที่ไม่มีหลักฐานเป็น `[ทีมกรอก]`
6. อัปเดต `HANDOFF.md` (บนสุด: วันที่ · สมาชิก · งาน · ไฟล์ · FR · ผล test จริง · ที่ยังขาด · branch/PR)
7. เพิ่มแถว AI log ใน `docs/02-requirements/spec.md` (ถ้ายังไม่มีไฟล์ ให้จดใน HANDOFF ไว้ก่อน): วันที่ · ใคร · เครื่องมือ ·
   ขออะไร · ได้อะไร · ช่อง "ทีมแก้/ตรวจอะไร" และ "บทเรียน" = `[ผู้ใช้กรอก]`
8. เสนอ (ไม่รันเอง): `git add` ไฟล์ที่เกี่ยว · ข้อความ commit "ทำอะไร เพราะอะไร + รหัส FR" · `git push` branch · เปิด PR ให้เพื่อน review

## ห้าม

- push หรือ commit เข้า `main` · `push --force` · merge PR เอง
- แต่งผลสัมภาษณ์ ผลทดสอบ คำพูดผู้ใช้ ตัวเลข หรือแหล่งอ้างอิง · เขียน reflection / contribution แทนทีม
- เพิ่มฟีเจอร์ ไลบรารี หรือหน้าจอที่ไม่มี FR/NFR · ใช้ ES modules · เพิ่ม server/DB/npm
- ทำหลายงานรวดเดียวโดยไม่ให้ผู้ใช้อ่าน — ทำทีละชิ้น ให้ผู้ใช้อ่านและอธิบายได้ทุกบรรทัด
