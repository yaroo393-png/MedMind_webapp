ทีมใช้ **Claude Code** (Anthropic · โมเดล Claude Opus 5.5 เป็นหลัก · Claude Sonnet 5.5 ในบางรอบสั้นวันที่ 24–25 ต.ค. เช่น ตอบคำถามเรื่อง GitHub และแก้ merge conflict ของเอกสาร)

AI ร่างเอกสาร เขียนโค้ดและ unit test (test ก่อนโค้ด) และทดสอบหน้าจออัตโนมัติในเบราว์เซอร์ ·

**ความโปร่งใสเรื่องผู้ทำงาน:** ตามที่ทีมตัดสิน 23/10/69 สมาชิก A (YAR OO) เป็นผู้สั่ง AI ร่างงานของทุกบทบาท · ทุกไฟล์ระบุ `เจ้าของ` (ตาม Charter §8) และ `ร่างโดย` ไว้ที่หัวไฟล์ ·
การตรวจของเจ้าของแต่ละส่วนบันทึกในช่อง "ทีมแก้/ตรวจอะไร" ของ AI log → [ทีมกรอก]

## 3. AI ผิดตรงไหน และจับได้อย่างไร (5 ความผิดพลาดของ AI · week06)

| แบบ | เกิดอะไร | จับได้ด้วย | แก้ |
|---|---|---|---|
| **Silent wrong logic** | กฎล็อกการเดารหัสในแผนของ AI ตัดครั้งผิดที่ 10 นาที → ปลดล็อกก่อนเวลา (FR-01) | unit test ค่าขอบ | ตัดที่ 20 นาที + แก้ architecture §8.3 |
| **Silent wrong logic** | มื้อ 23:50 มีช่วงยืนยันช้าว่าง → ผู้ดูแลไม่ได้รับแจ้งเลย (FR-05) | unit test ค่าขอบเที่ยงคืน | แจ้งได้จนจบวันของ T+15 |
| **Missing edge case** | spec บอกว่ายา 1 ตัวมีเวลา "หลังอาหาร + ก่อนนอน" ได้ แต่ data model เก็บค่าเดียว (FR-02) | `/speckit-analyze` | แก้ spec ให้ตรง + เพิ่ม test |
| **Missing edge case** | ✗4 ของ FR-03: มื้อที่ T+15 พอดีขัดกับคำสถานะ BR-14 | AI พบระหว่าง specify → **ถามผู้ใช้** | ผู้ใช้เลือกแสดงต่อจนหมดช่วงยืนยันช้า |
| **Hallucinated API** | หน้าเตือนเรียกฟังก์ชัน `store.notify` ที่ไม่มีอยู่จริง (FR-03) | รันในเบราว์เซอร์จริง | เปลี่ยนเป็นการเอาแถบออกเองในหน้า |
| **Over-engineering / ขัดกติกา** | ปุ่มหลัก "กินแล้ว" หลายปุ่มเมื่อมื้อซ้อน (ขัด "1 หน้าจอ 1 ปุ่มหลัก") · "กินแล้ว" ย้อนไม่ได้แต่ไม่มีการยืนยัน · พารามิเตอร์ที่ไม่ได้ใช้ | `/speckit-analyze` (CRITICAL 2 ครั้ง) · อ่านโค้ด | ปุ่มหลักเฉพาะมื้อแรก · ยกเลิกได้ 10 วินาที (ผู้ใช้เลือก) · ตัดพารามิเตอร์ |
| **Untrusted dependency** | ต้องมีตัวสร้าง QR เพิ่ม | AI เสนอ `qrcode-generator@1.4.4` แล้วตรวจ sha512 ตรง registry · ไม่มี dependency · ไม่เรียกเครือข่าย · ทดสอบสร้าง→อ่านกลับ | ผู้ใช้อนุมัติ |
| **ข้อมูลในเอกสารผิด** | นับผล test ผิด (เขียน 31/31 จริง 28/28) · เขียนว่า "FR-01 merge แล้ว" ทั้งที่ยัง · ข้อความใน wireframe 2 จุด · final report 3 จุด ไม่ตรงโค้ด/เอกสาร | AI ตรวจเทียบไฟล์จริงก่อนส่งมอบ | แก้ก่อน commit |
| **AI ตัดสินผิดเอง** | ADR-07 AI ตัดกล้องสดออก (อ่าน QR จากรูปอย่างเดียว) | **ผู้ใช้ทดสอบบนมือถือจริงแล้วไม่เห็นกล้อง** | เพิ่มกล้องสด + ทางสำรอง · แก้ ADR-07 |

**ข้อสังเกตจากหลักฐาน:** บั๊กตรรกะทั้ง 2 ตัวถูกจับโดย test ค่าขอบที่เขียนก่อนโค้ด · ปัญหาที่ขัดกติกาวิชาถูกจับโดย `analyze` ก่อนเขียนโค้ด · การตัดสินที่ผิดทางผู้ใช้ถูกจับโดยคนที่ลองบนอุปกรณ์จริง

## 5. ข้อมูลและความเป็นส่วนตัวกับ AI (NFR-09 · PDPA)

- **ระบบ (prototype) ไม่ส่งข้อมูลให้ AI หรือบริการภายนอก:** อ่านฉลากด้วย OCR ในเครื่อง (Tesseract.js ฝังในไฟล์) · ตรวจแล้วว่าตัดเน็ตแล้วอ่านได้และไม่มี request ออก
- **ระหว่างพัฒนา:** ผู้ใช้ส่งรูปถ่ายฉลากยาจริง 4 ใบให้ Claude Code ในเครื่องเพื่อทดสอบการอ่าน · ฉลากจริงมีข้อมูลส่วนตัวของผู้ป่วย →
  เก็บเฉพาะในโฟลเดอร์ `real-labels/` ที่ git ไม่เก็บ · ไม่คัดข้อความจริงลงไฟล์ใดใน repo · มี test ตรวจว่าร่างไม่มีชื่อผู้ป่วย/HN (SC-011) ·
  [ทีมกรอก — ได้รับความยินยอมจากเจ้าของฉลากหรือไม่ · ลบรูปจากเครื่องเมื่อใด]
- ชื่อจริงและช่องทางติดต่อของผู้ให้สัมภาษณ์ไม่อยู่ใน repo และไม่ได้ให้ AI

## 6. กลไกที่ใช้คุม AI

- **ไฟล์กติกาที่ AI ต้องอ่านทุกครั้ง:** `CLAUDE.md` · `SE-COURSE-PRINCIPLES.md` · constitution ของ Spec Kit (หลักการ 5 ข้อ: Golden Thread · No gold-plating · test ก่อนโค้ด · evidence over opinion · ความปลอดภัยผู้สูงอายุ)
- **Spec Kit:** 1 Must FR = 1 spec → `clarify` ถามคนก่อน → `analyze` ตรวจความขัดกันก่อนเขียนโค้ด → `implement` เขียน test ก่อนโค้ด
- **กติกา `[ทีมกรอก]`:** ข้อมูลที่ไม่มีหลักฐานต้องเว้นว่าง · AI ห้ามเขียน reflection/contribution แทนทีม
- **Git:** AI เสนอคำสั่ง ทีมเป็นคนรัน · ห้าม push เข้า main · 1 งาน = 1 branch + PR
- **บันทึก:** AI log ทุกครั้งที่ใช้ + `HANDOFF.md` ทุกครั้งที่จบงาน

## 7. ข้อจำกัดที่ทราบ

- ผลกับผู้ใช้จริงยังไม่มี (NFR-02, NFR-08, NFR-11, SUS) — งานที่ AI ทำผ่าน verification แล้ว แต่ **validation กับผู้ใช้ยังไม่ได้ทำ**
- สคริปต์ทดสอบในเบราว์เซอร์อยู่ในพื้นที่ชั่วคราวของ AI ไม่อยู่ใน repo → ผู้ตรวจรันซ้ำจาก repo ไม่ได้ (ใช้ quickstart ทดสอบมือแทน)
- diagram Mermaid ใน `user-flow.md` ยังไม่ได้ render ตรวจด้วยเครื่องมือ → ตรวจบน GitHub
- AI log บางแถวไม่เรียงตามวันที่ (เพิ่มต่อกันตามลำดับที่ทำ) · ช่อง "ทีมแก้/ตรวจอะไร" และ "บทเรียน" ส่วนใหญ่ยังเป็น `[ผู้ใช้กรอก]`
